# ADR-001 Устройство плагина

> **Решение:** плагин `task` из скилов (`/task:next`, `/task:create`, `/task:help` …) + хуки на Node; репозиторий — локальный маркетплейс, плагин лежит в `plugin/`.
> **Почему:** скилы — актуальный формат команд, имя плагина становится префиксом команд, а хуки Stop/PostToolUse дают контроль статусов.
> **Следствия:** все команды вызываются с префиксом `task:`; для хуков нужен Node в PATH; правила формата доходят до агентов тремя путями.

## Контекст

Источники:

- Официальная документация: plugins-reference / manifest-reference, plugins/create, plugins/install, hooks (code.claude.com, проверено 2026-09-27).
- Установленный маркетплейс `claude-plugins-official`: `plugin-dev` (скилы про структуру плагинов и хуки), `example-plugin`, `ralph-loop` (Stop-хук), `learning-output-style` (SessionStart-хук).

## Решение

### 1. Структура и манифест

```
C:\AI\claude-tasks\                 ← репозиторий = локальный маркетплейс
├── .claude-plugin/marketplace.json  ← список из одного плагина: source "./plugin"
├── plugin/                          ← корень плагина
│   ├── .claude-plugin/plugin.json   ← name: "task"
│   ├── skills/<команда>/SKILL.md    ← команды и фоновые знания
│   ├── hooks/hooks.json
│   ├── scripts/tasks.mjs            ← скрипт графа/доски/хуков (Node, без зависимостей)
│   └── templates/                   ← шаблоны задач для init
└── Docs/                            ← план разработки самого плагина (в плагин не входит)
```

- Манифест `plugin/.claude-plugin/plugin.json`; обязателен только `name`. Все остальные папки — в корне плагина, **не** внутри `.claude-plugin/`.
- `Docs/` вынесен за пределы плагина, чтобы план разработки не устанавливался пользователям.
- `${CLAUDE_PLUGIN_ROOT}` — путь к установленному плагину (меняется при обновлении, писать туда нельзя). `${CLAUDE_PLUGIN_DATA}` — постоянная папка данных плагина. `${CLAUDE_PROJECT_DIR}` — корень проекта.

### 2. Скилы или команды

- `commands/*.md` — **устаревший** формат; `skills/<name>/SKILL.md` — рекомендуемый. Загружаются одинаково.
- Скил бывает двух видов: вызываемый пользователем (`/имя`, с `argument-hint`) и фоновый — модель сама подключает его по `description`.
- **Все компоненты плагина получают префикс имени плагина:** `/<plugin>:<skill>`. Поэтому имя плагина выбрано коротким — `task`:

| Команда | Что делает |
|---------|-----------|
| `/task:help` | Список команд и как устроен план |
| `/task:init` | Создать `Docs/Tasks/` в проекте |
| `/task:create` | Обсудить и создать задачу |
| `/task:split` | Разбить эпик/фичу |
| `/task:next` | Взять следующую готовую задачу |
| `/task:done` | Закрыть задачу |
| `/task:replan` | Пересмотреть будущие задачи |
| `/task:idea` | Идея в бэклог |
| `/task:board` | Проверка графа + доска |

Имя репозитория (`claude-tasks`) и имя плагина (`task`) независимы.

### 3. Как агенты узнают правила формата

Три пути — от самого надёжного к запасному:

1. **SessionStart-хук** возвращает `additionalContext`: короткие правила ведения задач + какие задачи сейчас `in-progress`. Лимит — 10 000 символов, поэтому только суть и ссылка на полный формат.
2. **Фоновый скил `task:format`** — полная спецификация (результат F01-01); модель подключает его, когда работает с файлами `Docs/Tasks/`. Команды плагина ссылаются на него явно.
3. **Блок в `CLAUDE.md` проекта**, который пишет `/task:init` (F04-01) — виден любому агенту, даже если плагин не установлен.

Хуки плагина срабатывают и внутри субагентов (у событий есть `agent_id`/`agent_type`), так что субагенты тоже под контролем.

### 4. Хуки для контроля статусов (F04-07)

| Событие | Использование |
|---------|--------------|
| `SessionStart` | Правила + текущие `in-progress` задачи в контекст |
| `PostToolUse` (matcher `Write\|Edit\|MultiEdit`) | Если правился файл плана — пересобрать доску и прогнать проверку; ошибки **этой правки** вернуть агенту (`decision: block`). Если правка сама перевела задачу в `in-progress` — записать «сессия → задача» (см. ниже) |
| `Stop` / `SubagentStop` | Если **эта** сессия владеет `in-progress` задачей без свежей записи в «Журнале» — `{"decision": "block", "reason": "…обнови статус и журнал…"}` |

Важные детали:

- **Stop срабатывает во всех сессиях проекта** (урок из `ralph-loop`), поэтому нужно владение «сессия → задача»: напоминание получает только та сессия, которая взяла задачу. Для этого — запись по `session_id` (где и кто её пишет — ниже).
- Во входе Stop есть `stop_hook_active` — если `true`, повторно не блокировать (защита от бесконечного цикла).
- `last_assistant_message` на Stop надёжнее чтения транскрипта (транскрипт пишется с задержкой).
- Выключатель хуков — переменная окружения проекта `TASK_HOOKS=off` (`"env"` в `.claude/settings.json`). ~~`userConfig`~~ — отказались в F04-07: он задаётся на пользователя, а не на проект, и может показывать диалог настройки при установке.
- Владение «сессия → задача» — ~~в `${CLAUDE_PLUGIN_DATA}/sessions.json`, запись из PostToolUse по тексту команды~~ (F08-01: regex по команде давал ложные и пропущенные напоминания, а хук на каждый Bash стоил ~80 мс во всех проектах) → в служебной папке плана `<план>/.claude-tasks/sessions/<session_id[:agent_id]>.json` (скрыта, в git не попадает). Пишет его сам `tasks.mjs set`, когда задача переходит в `in-progress` (или с `--take`): ID сессии есть в окружении Bash — `CLAUDE_CODE_SESSION_ID` (проверено в CLI и в десктопе), SessionStart дублирует его в `TASK_SESSION_ID` через `CLAUDE_ENV_FILE`. Правку файла, которая сама ставит `in-progress`, записывает хук PostToolUse. Точка отсчёта — число записей журнала после взятия.
- План плагина узнаётся по доске `Board.md` с пометкой генератора (F08-01): чужая папка `docs/tasks` без неё — не план, хуки её не трогают.

### 5. Скрипт

- Один файл `scripts/tasks.mjs` на Node без npm-зависимостей: `check`, `board`, `next --json`, `hook <event>`.
- Из хуков: `node "${CLAUDE_PLUGIN_ROOT}/scripts/tasks.mjs" hook stop`. Из скилов — та же строка через Bash.
- Требование: `node` в PATH (у пользователя v24). Python не используем.

### 6. Установка

- **Разработка:** `claude --plugin-dir C:\AI\claude-tasks\plugin` (только CLI, на одну сессию), после правок — `/reload-plugins`.
- **Постоянно:** добавить репозиторий как маркетплейс и поставить плагин:
  - `claude plugin marketplace add C:\AI\claude-tasks`
  - `claude plugin install task@claude-tasks` (user scope — во всех проектах)
- Терминал, десктоп-приложение и VS Code читают одни и те же настройки: установленный в одном месте плагин виден во всех.
- ~~Плагин из локального маркетплейса грузится «на месте» и не фиксируется по версии — правки в репозитории подхватываются после `/reload-plugins`.~~ Неверно (F08-01): установка — снимок в `~/.claude/plugins/cache/claude-tasks/task/<версия>/`, сессии грузят его. После правок — поднять версию и `claude plugin marketplace update claude-tasks`, `claude plugin update task@claude-tasks`.
- Проверка манифеста: `claude plugin validate`.

### Проверено в F02-02 (2026-09-27, Claude Code 2.1.283)

- **Без префикса работает, если имя не занято:** `/format` = `/task:format`. Имена `help`, `init` заняты встроенными командами, поэтому основная форма — `/task:<команда>`.
- **`source: "./plugin"`** в локальном маркетплейсе на Windows работает; `claude plugin validate` проходит для плагина и маркетплейса.
- ~~**Загрузка «на месте» подтверждена:** при установке создаётся снимок в `~/.claude/plugins/cache/claude-tasks/task/0.1.0/`, но новая сессия видит правки из репозитория без переустановки.~~ Опровергнуто в F08-01: сессия десктоп-приложения 2026-09-27 загрузила скил `task:format` из снимка `cache/claude-tasks/task/0.1.0` (коммит 05875da, без скрипта и хуков), а не из репозитория.
- `--scope local` пишет `enabledPlugins` в `.claude/settings.local.json` репозитория; маркетплейс регистрируется в пользовательских настройках.
- **Windows:** агент вызывает `node` через инструмент PowerShell, поэтому в `allowed-tools` скилов — правила и для Bash, и для PowerShell; без второго каждый вызов скрипта требовал подтверждения (найдено в F04-07). ~~`Bash(node:*), PowerShell(node:*)`~~ разрешали без запроса любой `node -e …` → с F08-01 правило сужено до скрипта плагина: `Bash(node "${CLAUDE_PLUGIN_ROOT}/scripts/tasks.mjs":*)` (и так же для PowerShell). Проверено `claude -p`: `${CLAUDE_PLUGIN_ROOT}` подставляется и в `allowed-tools`, вызов скрипта (в том числе с here-doc `--log - <<'EOF'`) проходит без запроса, без правила — отказ.
- `${CLAUDE_PLUGIN_ROOT}` подставляется и в тексте скила (проверено в F04-01): скилы вызывают `node "${CLAUDE_PLUGIN_ROOT}/scripts/tasks.mjs" …`.
- Для проверки команд без установки: `claude -p "/task:…" --plugin-dir C:\AI\claude-tasks\plugin` в любой папке.
- Отображение команд в меню `/` десктоп-приложения — проверяет пользователь (после `/reload-plugins`).

### Было не проверено (исходный список)

- Работает ли вызов без префикса (`/next`), если нет конфликтов. Документация везде показывает `/<plugin>:<skill>` — исходим из префикса.
- Корректен ли `source: "./plugin"` в `marketplace.json` для локального маркетплейса на Windows.
- Как десктоп-приложение показывает команды плагина в меню `/`.

## Отвергнутые варианты

- **`commands/`** — устаревший формат.
- **MCP-сервер** для работы с задачами — избыточно: файлы и так читаются стандартными инструментами, а скрипт закрывает проверки.
- **Отдельный агент или профиль на каждую роль** в плагине — отказались: готовых ролей нет, `role` — свободная метка; с планом работают обычные агенты пользователя по общей спецификации (решение #7 в [[F-01 Формат задач]]).

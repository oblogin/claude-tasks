# F08-01 Дефекты из код-ревью

> **Что:** исправить все дефекты, найденные код-ревью плагина: скрипт `tasks.mjs`, хуки, скилы, шаблоны.
> **Зачем:** дефекты переносят не те папки, портят журнал и ID, срабатывают в чужих проектах и выдают агентам не те задачи.
> **Готово, когда:** каждый дефект воспроизводится тестом до исправления и не воспроизводится после, все тесты зелёные.

## Воспроизведение

Все пункты воспроизведены на временных проектах при ревью (2026-09-27):

1. `move F-02 --to E-02`, когда заметка фичи лежит прямо в папке эпика → весь эпик E-01 переезжает внутрь E-02.
2. Проект с папкой `docs/tasks` на Windows → хуки считают её планом: пишут туда `Board.md`, требуют «исправить» чужие документы; `init` при существующей `docs/` создаёт `docs/Tasks`, который на Linux не находится.
3. `--log "…"` с Markdown: PowerShell 5.1 превращает `` `t ``/`` `n `` в TAB и перевод строки, теряет `$5` и кавычки; bash выполняет содержимое обратных кавычек как команду.
4. Правка своей задачи → хук блокирует из-за давней чужой ошибки в другом файле.
5. `![[схема.png]]`, `[[Имя.md]]`, код в блоке внутри пункта журнала → «битые ссылки».
6. replan пишет журнал чужой in-progress задачи `set <ID> in-progress` → сессия replan получает напоминание Stop; `set --json ID in-progress` и `node "$S" set …` не распознаются.
7. Битая зависимость → задача выдаётся `next`; отменённая зависимость блокирует навсегда без предупреждения; задачи отменённой фичи выдаются `next`.
8. После `move` старый ID выдаётся снова; следующий перенос переписывает историю в журнале.
9. `/task:next <ID>` берёт чужую in-progress задачу, задачу на проверке и draft.
10. `migrate`: цепочка замен ID даёт дубль; ID в названии другой задачи переписывается без переименования файла; `$&`, `$1`, `$$` в названиях портят ссылки.
11. Файл с UTF-8 BOM → «нет frontmatter», задача выпадает из графа.
12. Вложенный проект: хук смотрит в один план, скрипт — в другой; владение задачей теряется при переходе сессии в другой проект.
13. Пустой `- [ ] ` из шаблона считается критерием — ready-задача без критериев проходит проверку.
14. Две сессии одновременно создают задачу → одинаковые ID.
15. `allowed-tools: Bash(node:*)` в скилах разрешает любой `node -e …` без запроса.

Мелкие (вне лимита отчёта): хук стоит ~86 мс на каждый вызов Bash/Edit во всех проектах; `move` одной задачи перезаписывает почти все файлы плана; запись `set --log` уходит в конец файла, если после «Журнала» есть раздел; `set` без строки `status` «успешен» без изменений, без `id` — падает; задача с названием «… Board» не проверяется хуком; `init` переводит CRLF в `CLAUDE.md` в LF; исключения CLI печатают стек; пустые папки пользователя удаляются при `move`/`migrate`; название с точкой в конце на Windows расходится с заголовком.

**Ожидалось:** план не портится ни одной командой, хуки работают только в планах плагина и только по своим задачам, журнал записывается как написан.
**Получилось:** см. пункты выше.

## Критерии готовности

- [x] 1. `move` фичи переносит только собственную папку фичи; фича или цель не в своей папке — понятная ошибка с подсказкой `migrate`
- [x] 2. План распознаётся по доске плагина и имени папки без учёта регистра; хуки молчат в чужой `docs/tasks`; `init` не смешивает план с чужими файлами
- [x] 3. Журнал можно передать без оболочки (`--log -` из stdin, `--log-file`); многострочная запись оформляется вложенным списком; скилы и контекст SessionStart учат безопасной передаче
- [x] 4. Хук после правки сообщает только ошибки, связанные с изменённым файлом
- [x] 5. Вложения и ссылки `[[Имя.md]]` / `[[путь/Имя]]` на существующие файлы не считаются битыми; код в блоках с отступом и в двойных обратных кавычках не проверяется
- [x] 6. Владение задачей записывает сам `set` при переходе в in-progress (ID сессии из окружения) и с явным `--take`, хук — при правке, ставящей in-progress; replan не «присваивает» чужую задачу; порядок флагов и переменные не мешают
- [x] 7. Очередь: неразрешённая зависимость блокирует; зависимость от cancelled — предупреждение и подсказка в `set cancelled`; задачи закрытых фич и эпиков не выдаются, `check` предупреждает
- [x] 8. ID не переиспользуются: прежние ID хранятся в `former_ids` и учитываются при выдаче; `show`/`set` находят задачу по прежнему ID
- [x] 9. `/task:next <ID>` разбирает in-progress, review и draft отдельно
- [x] 10. Переименования ID — одним проходом; ID в названиях других задач, заголовках, frontmatter и журналах не переписываются; `$` в названиях не портит подстановки
- [x] 11. Файлы с BOM читаются; при записи сохраняются BOM и переводы строк файла
- [x] 12. Хук и скрипт ищут план одной функцией; владение хранится в каждом плане отдельно — работа сессии в другом проекте его не сбрасывает
- [x] 13. Пустой пункт и пункт из одной подсказки не считаются критерием; оставшиеся подсказки шаблона — предупреждение
- [x] 14. `new`, `set`, `move`, `migrate` работают под блокировкой плана — параллельные сессии не получают один ID
- [x] 15. `allowed-tools` скилов разрешают без запроса только скрипт плагина (проверено `claude -p`)
- [x] 16. Хук после правок не запускается на каждый Bash (только Write/Edit/MultiEdit) и не перечитывает план лишний раз
- [x] 17. `move`/`migrate` пишут только изменённые файлы и удаляют только папки, опустевшие из-за переноса
- [x] 18. `set`: запись попадает в раздел «Журнал»; нет строки `status` — добавляется; нет `id` — понятная ошибка; итоговые сообщения точные
- [x] 19. Хук узнаёт доску по точному пути, а не по окончанию имени
- [x] 20. `init` сохраняет переводы строк и BOM `CLAUDE.md` и `.gitignore`
- [x] 21. CLI: ошибки без стека; флаги без значения — понятное сообщение; `list --type` принимает несколько типов; ID из имён файлов учитываются при выдаче новых
- [x] 22. Название с точкой или пробелом в конце, с управляющими символами — отказ с объяснением
- [x] 23. Формат, скилы и README описывают новое поведение; README не обещает загрузку плагина «на месте»
- [x] 24. На каждый пункт — тест; все тесты зелёные; `check` плана плагина и примера — без ошибок

## Детали

- Отчёт ревью — в сессии 2026-09-27; сценарии воспроизведения — в пунктах выше.
- Решения:
  - план плагина узнаётся по `Board.md` с пометкой генератора — она есть в каждом плане, созданном `init` или скриптом; отдельный файл-маркер не нужен;
  - прежние ID — поле `former_ids` (задачи); по нему ID не выдаются повторно и находятся старыми ссылками в тексте;
  - владение задачей пишет сам `set` (ID сессии — `CLAUDE_CODE_SESSION_ID` в окружении Bash) в служебную папку плана `.claude-tasks/`; хук — только для правки файла, ставящей in-progress; продолжить задачу в новой сессии — `set <ID> in-progress --take`. Поэтому PostToolUse больше не нужен на Bash.
- Установленный у пользователя плагин — снимок коммита `05875da` в `~/.claude/plugins/cache/claude-tasks/task/0.1.0` (без скрипта и хуков, старый плоский формат): сессии грузят его, а не папку репозитория. Обновление — `claude plugin update task@claude-tasks`; README это должен говорить.

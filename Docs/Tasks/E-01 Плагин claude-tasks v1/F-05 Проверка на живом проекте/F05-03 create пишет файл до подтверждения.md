# F05-03 create пишет файл до подтверждения

> **Что:** `/task:create` создаёт и заполняет файлы задачи до того, как пользователь подтвердил черновик, а сам черновик показывает сокращённой сводкой.
> **Зачем:** пользователь не видит, что именно попадёт в план, а отказ от черновика оставляет в плане лишние файлы и занятые ID.
> **Готово, когда:** в живом диалоге файл появляется только после «да», а перед этим черновик показан целиком.

## Воспроизведение

1. Интерактивная сессия в `examples/guess-number` с плагином 0.3.0, команда `/task:create задача: звук при победе`.
2. Два вопроса по одному (оформить фичей; звук — системный BEL).
3. Агент вызывает `tasks.mjs new` для фичи и задачи, записывает тело файлов и только потом спрашивает «Подтверждаете содержимое?».

**Ожидалось:** черновик (frontmatter и тело) показан в ответе целиком, файл пишется после подтверждения — шаги 3–4 скила `create`.
**Получилось:** файлы `F-05 Звук при победе` и `F05-01 Бип при победе` созданы до вопроса; в ответе — сводка из нескольких строк; в критериях — «при проигрыше сигнал не звучит», хотя по ADR-001 примера проигрыша в MVP нет.

## Критерии готовности

- [ ] Скил `create` запрещает `tasks.mjs new` и правку файлов до подтверждения черновика; ID для черновика — через `new-id` с пометкой «будет выдан при записи»
- [ ] Скил требует показать черновик в ответе целиком (frontmatter и тело), а не сводкой
- [ ] Скил требует сверить критерии с ADR и задачами, на которые опирается новая задача (родитель, зависимости)
- [ ] Если в одном обсуждении создаются фича и задача — оба черновика показаны до записи, записываются после одного подтверждения
- [ ] Живой прогон `/task:create` в `examples/guess-number` проверен человеком: до «да» новых файлов нет, после отказа план не меняется

## Детали

- Скил: `plugin/skills/create/SKILL.md`, разделы «3. Показать черновик» и «4. Записать». Правило «Без подтверждения файл не пиши» уже есть, но модель его обходит — вероятно, чтобы получить ID и путь для черновика, вызывает `new` сразу.
- `new-id <тип> --parent <ID>` выдаёт следующий ID без создания файла; у фичи, которой ещё нет, ID задачи предсказать можно как `<Fnn>-01`.
- Правило стоит вынести в начало скила жирным пунктом — чтобы оно было видно до шага записи.
- Найдено в [[F05-01 Полный цикл на тестовом проекте]]; тестовые файлы из прогона удалены.
- После правки — поднять `version` плагина и обновить установку (`--scope user`).

## Проверка

1. `node --test plugin/scripts/test/*.test.mjs` — тесты зелёные.
2. Интерактивная сессия в `examples/guess-number`, `/task:create задача: звук при победе`: до ответа «да» `git status examples/` чистый; черновик виден целиком; после «нет» файлов нет.
3. Повторить с ответом «да» — файлы созданы, `tasks.mjs check` без ошибок; затем удалить тестовые файлы.

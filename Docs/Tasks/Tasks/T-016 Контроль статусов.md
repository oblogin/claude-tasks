# T-016 Контроль статусов

> **Что:** хуки плагина, которые не дают агенту закончить работу, не обновив статус и журнал задачи.
> **Зачем:** агенты забывают обновлять задачи, если работа закончилась без `done`, — доска начинает врать.
> **Готово, когда:** агент, бросивший задачу в `in-progress` без записи в журнале, получает напоминание и обновляет её до конца сессии.

## Критерии готовности

- [ ] Хук в конце ответа/сессии: если есть `in-progress` задача, а в её «Журнале» нет записи за эту сессию — агенту возвращается напоминание обновить статус и журнал
- [ ] Хук после правки файлов в `Docs/Tasks/`: прогон проверки T-006, ошибки возвращаются агенту сразу
- [ ] Хуки не мешают работе вне задач (нет `in-progress` — молчат)
- [ ] Хуки можно выключить в настройках проекта

## Детали

Выросло из идеи [[I-002 Хук-напоминание обновить задачу]]. Какие события хуков доступны плагину и как им вернуть сообщение агенту — выясняется в [[T-004 Research механики плагинов]].

Возможное дополнение (решить в работе): соглашение о коммитах `T-042: ...`, чтобы `done` мог показать коммиты задачи в журнале.

## Проверка

1. Взять задачу через `next`, сделать правку кода и закончить ответ без `done` — появляется напоминание.
2. Сломать ссылку в `depends_on` — хук сообщает об ошибке сразу после правки.

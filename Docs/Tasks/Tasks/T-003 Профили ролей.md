# T-003 Профили ролей

> **Что:** описать, как задачи ведут четыре роли — programmer, architect, gamedesigner, devops.
> **Зачем:** у разных ролей разные задачи; формат общий, но что писать в «Деталях» и что считать «готово» — у каждой своё.
> **Готово, когда:** на каждую роль есть профиль, и новую роль можно добавить, скопировав профиль.

## Критерии готовности

- [x] Профиль роли: какие типы задач она создаёт, какие подразделы «Деталей» заполняет, как выглядят её критерии готовности и «Проверка»
- [x] Для каждой роли — пример хорошей задачи (короткий)
- [x] Описано, как добавить свою роль в проекте (профиль в `Docs/Tasks/Roles/` переопределяет профиль плагина)

## Детали

Черновые акценты:

- **gamedesigner** — механика, ощущения игрока, параметры и баланс, референсы; «готово» = играбельно и проверено руками.
- **architect** — контракты, границы модулей, ADR, риски; часто research-задачи.
- **programmer** — затронутые файлы, шаги реализации, тесты; «готово» = собирается, тесты зелёные.
- **devops** — окружение, пайплайн, секреты (без значений), откат.

1. По каждому профилю создать задачу через `create` (после F-04) — агент заполняет правильные разделы.

# T-007 Генерация доски и кандидатов next

> **Что:** скрипт пересобирает `Board.md` и умеет выдать список задач, готовых к работе.
> **Зачем:** доска — точка входа для человека, список кандидатов — для команды `next`.
> **Готово, когда:** `Board.md` генерируется без ручных правок, а кандидаты `next` совпадают с тем, что видно на доске.

## Критерии готовности

- [ ] `Board.md`: дерево эпик → фича → задача со статусами; разделы «Готово к работе», «В работе», «Заблокировано (чем)», «Бэклог»
- [ ] Во всех таблицах и списках доски задачи идут по порядку ID (T-002 перед T-016); в «Ждёт» — только незакрытые зависимости, номера — ссылками вида `[[T-005 …\|T-005]]` (требование пользователя)
- [ ] Для каждой задачи обратные связи «блокирует» вычисляются, а не хранятся
- [ ] Кандидаты `next`: `ready` + все `depends_on` в `done`; сортировка: текущий спринт → приоритет → число задач, которые она разблокирует
- [ ] Фильтр кандидатов по роли (`--role gamedesigner`)
- [ ] `Board.md` помечен как сгенерированный (ручные правки перезаписываются)

## Проверка

1. На плане этого репозитория доска совпадает с ручной `Board.md`.

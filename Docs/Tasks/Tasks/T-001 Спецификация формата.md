# T-001 Спецификация формата

> **Что:** написать спецификацию формата — единственный документ, по которому любой агент создаёт и ведёт задачи.
> **Зачем:** это контракт для всех команд, скрипта и ролей; всё остальное строится поверх него.
> **Готово, когда:** в спецификации закрыты все вопросы из «Деталей», а файлы этого плана ей соответствуют.

## Критерии готовности

- [x] Описаны типы: epic, feature, task, research, bug, idea — и когда какой использовать
- [x] Описаны поля frontmatter: обязательные / необязательные, допустимые значения
- [x] Описаны статусы и допустимые переходы (`idea → draft → ready → in-progress → review → done`, плюс `cancelled`); `blocked` — вычисляется, не хранится
- [x] Описаны правила ID и имён файлов
- [x] Описаны обязательные разделы каждого типа, в том числе правила блока «Коротко»
- [x] Описано, как агент ведёт задачу — обязательные правила обновления статуса (решение #6 в [[F-01 Формат задач]]): взял → `in-progress`; закончил → `review` или `done` + запись в «Журнал» + отмеченные критерии; упёрся или отложил → запись в «Журнал» с причиной; статус меняется в том же шаге, что и работа, а не «потом»
- [x] Файлы этого плана (`Docs/Tasks/`) приведены в соответствие со спецификацией

## Детали

Спецификация — фоновый скил плагина `task:format`: `plugin/skills/format/SKILL.md` (так её получают агенты, см. [[ADR-001 Устройство плагина]], раздел 3). Решения по открытым вопросам:

1. **Имя файла.** Остаётся `<ID> <Название>.md` — читаемо в Obsidian. Имя стабильно; переименование только вместе с правкой всех ссылок; битые ссылки ловит скрипт.
2. **ID.** Максимальный номер префикса + 1, номера не переиспользуются. `E-`/`F-` — две цифры, `T-`/`I-`/`ADR-` — три. task, research и bug делят нумерацию `T-`.
3. **Раскладка.** По типам: `Epics/`, `Features/`, `Tasks/` (task, research, bug), `Backlog/`, `Adr/`, необязательная `Roles/`. ADR перенесены внутрь `Docs/Tasks/`, чтобы план был самодостаточным.
4. **Ссылки во frontmatter.** Формат на них опирается (`parent`, `depends_on`). **Не проверено в Obsidian** — нужна проверка человеком, поэтому задача в `review`.
5. **«Коротко».** Цитата сразу под заголовком: Что / Зачем / Готово, когда; у idea — Что / Зачем; у adr — Решение / Почему / Следствия. Узнаётся по положению, а не по языку.
6. **Research → ADR.** Отдельный тип `adr` с префиксом `ADR-`, статусы `proposed → accepted → superseded`.
7. **Журнал.** `- **YYYY-MM-DD · роль (кто):** текст`, новые записи внизу.

Дополнительно: заголовки разделов фиксированы (таблица в разделе 10 спецификации). Позже решено: только русский язык, без выбора языка (см. журнал [[T-002 Шаблоны файлов]]).

## Проверка

1. Прочитать `plugin/skills/format/SKILL.md` «как новый агент» — по нему можно создать корректную задачу без других подсказок.
2. Все файлы в `Docs/Tasks/` проходят правила спецификации.
3. Открыть `Docs/Tasks/` в Obsidian → Graph view: задачи связаны с фичами (`parent`) и между собой (`depends_on`).

# ADR-001 Диапазон и правила партии

> **Решение:** число загадывается в диапазоне 1–100 включительно, догадка — целое в десятичной записи, попыткой считается каждая корректная догадка, лимита попыток в MVP нет.
> **Почему:** 1–100 даёт партию в 5–10 ходов (оптимум 7), где подсказки явно ведут к цели, а строгие правила ввода однозначно превращаются в тесты.
> **Следствия:** логика, разбор ввода, тексты и шкала оценки опираются на `min = 1`, `max = 100`, оптимум 7 и четыре кода ошибок ввода без отдельного кода для повтора.

## Контекст

Эпик [[E-01 MVP игры Угадай число]]: одиночная консольная игра на русском, без лимита попыток в MVP. От правил зависят:

- [[F01-04 Логика партии]] — диапазон, подсчёт попыток;
- [[F02-02 Разбор догадки]] — что считать корректным вводом и какие коды ошибок возвращать;
- [[F01-03 Тексты партии]], [[F02-01 Тексты ошибок ввода]] — что говорить игроку;
- [[F04-01 Шкала оценки по попыткам]] — оптимум для порогов.

Оптимум при двоичном поиске для N чисел — ⌈log₂(N + 1)⌉ попыток: столько гарантированно хватает при лучшей стратегии.

## Решение

### 1. Диапазон

- `min = 1`, `max = 100`, **обе границы включительно** — 100 возможных чисел.
- Оптимум: ⌈log₂(101)⌉ = **7 попыток**. Это число берёт шкала оценки [[F04-01 Шкала оценки по попыткам]].
- Границы — константы в одном месте кода (передаются в `createGame` и `parseGuess`), а не литералы по модулям: уровни сложности после MVP будут менять именно их.

### 2. Загадывание

- Число — равномерно случайное целое из `[min, max]`: `min + Math.floor(random() * (max - min + 1))`, где `random` возвращает значение из `[0, 1)`.
- Каждая партия загадывает число **независимо**: оно может совпасть с числом прошлой партии (вероятность 1 %). Исключать совпадение не нужно — игрок его не заметит как ошибку, а правило «независимо» проще тестировать.

### 3. Допустимый ввод

Строка разбирается по шагам, первый сработавший определяет результат:

| # | Условие (после обрезки пробельных символов по краям) | Результат |
|---|------------------------------------------------------|-----------|
| 1 | Строка пустая | ошибка `empty` |
| 2 | `^[+-]?[0-9]+$` — необязательный знак и только ASCII-цифры | целое; дальше проверка диапазона (шаг 5) |
| 3 | `^[+-]?[0-9]*[.,][0-9]+$` или `^[+-]?[0-9]+[.,]$` — одна десятичная точка или запятая | ошибка `notInteger` |
| 4 | Всё остальное | ошибка `notNumber` |
| 5 | Целое вне `[min, max]` | ошибка `outOfRange`; иначе — корректная догадка |

Уточнения:

- **Пробелы по краям** (пробел, таб, `\r`) отбрасываются — `String.prototype.trim()`. Пробелы **внутри** (`4 2`) → `notNumber`.
- **Ведущие нули** разрешены: `007` → 7, `0100` → 100.
- **Знак** разрешён: `+42` → 42; `-5` и `-0` → целое вне диапазона → `outOfRange` (игроку полезнее «от 1 до 100», чем «это не число»).
- **Дробь** — и через точку, и через запятую (русская раскладка): `3.5`, `3,5`, `.5`, `3.` → `notInteger`. Запись с нулевой дробной частью (`3.0`) — тоже `notInteger`: правило «целое пишется без разделителя» проще объяснить и проверить.
- **Не число**: `abc`, `12abc`, `4 2`, `1e2`, `0x10`, `Infinity`, `+`, `-`, `.`, `1.2.3`, цифры не из ASCII (`４２`).
- `1,000` подходит под шаг 3 и даёт `notInteger` — разделители разрядов не поддерживаются; для диапазона до 100 это не нужно.
- **Очень длинные числа** (`99999999999999999999`) → `outOfRange`; разбор не должен терять точность так, чтобы такое число попало в диапазон (достаточно `Number()` по строке, прошедшей шаг 2: результат всё равно > `max`).

Примеры для тестов:

| Ввод | Результат |
|------|-----------|
| `42` | 42 |
| `" 42 "`, `"\t42\r"` | 42 |
| `007` | 7 |
| `+42` | 42 |
| `1`, `100` | 1, 100 (границы) |
| `0`, `101`, `-5`, `-0` | `outOfRange` |
| `""`, `"   "` | `empty` |
| `3.5`, `3,5`, `.5`, `3.`, `3.0` | `notInteger` |
| `abc`, `12abc`, `4 2`, `1e2`, `0x10`, `Infinity`, `+`, `.`, `1.2.3` | `notNumber` |

### 4. Что считается попыткой

- Попытка — **каждая корректная догадка** (прошла шаги 1–5), включая победную: угадал с первого ввода — 1 попытка.
- **Неверный ввод** (любой код ошибки) попыткой **не считается**: игрок получает сообщение об ошибке и вводит снова.
- **Повтор** уже названного числа — обычная попытка: засчитывается и получает обычную подсказку «больше / меньше». Отдельного кода ошибки и текста (`errorRepeat`) **нет**. Повтор — промах игрока, а не опечатка; он честно наказывается счётчиком и оценкой, а логике не нужно хранить историю догадок.

### 5. Лимит попыток

- В MVP лимита **нет** — подтверждаем эпик: партия длится до победы, проигрыша не существует. Лимит — вместе с уровнями сложности после MVP.

### Непроверенные допущения

- 1–100 не слишком долго и не слишком коротко для одной партии, а 7 — адекватный ориентир для шкалы — проверит [[F04-03 Плейтест и баланс]].

## Отвергнутые варианты

- **1–10** — оптимум 4 попытки, партия заканчивается раньше, чем подсказки начинают ощущаться; оценке почти нечего различать.
- **1–1000** — оптимум 10 попыток, реальная партия тянется 12–20 ходов; для первой игры скучно. Кандидат на «сложный» уровень после MVP.
- **Считать неверный ввод попыткой** — опечатка «съедала» бы ход, что противоречит цели [[F-02 Защита от неверного ввода]].
- **Отдельная ошибка на повтор числа** (не засчитывать, напомнить) — дружелюбнее, но требует истории догадок, ещё одного кода и текста; для MVP лишнее. Можно вернуть идеей после плейтеста.
- **Разрешить `3.0` как 3** — ещё одно исключение в правилах ради редкого ввода.
- **Запретить знак** (`-5` → `notNumber`) — сообщение «это не число» на отрицательное число сбивает с толку.
- **Не повторять число прошлой партии** — лишнее состояние между партиями без заметной пользы.

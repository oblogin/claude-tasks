# F01-01 Правила и диапазон

> **Что:** выбрать диапазон загадываемого числа и точные правила партии: что считается попыткой, какие числа допустимы, есть ли лимит.
> **Зачем:** от этих правил зависят логика, разбор ввода, тексты и шкала оценки — их нельзя начать без решения.
> **Готово, когда:** есть ADR, который отвечает на все вопросы ниже, и программист может писать логику и разбор ввода, не переспрашивая.

## Критерии готовности

- [x] Диапазон выбран (границы включительно или нет) и обоснован — сколько попыток нужно при оптимальной игре
- [x] Определено, какой ввод допустим: только целые, знак, пробелы по краям, ведущие нули
- [x] Определено, что считается попыткой: засчитывается ли неверный ввод и повтор того же числа
- [x] Решено, есть ли в MVP лимит попыток (эпик относит лимит к «После MVP» — подтвердить или обосновать отказ)
- [x] Определено, может ли загаданное число совпасть с загаданным в прошлой партии
- [x] Решение записано в ADR (`Adr/`), impl-задача может стартовать без повторного исследования

## Детали

- Опора — эпик [[E-01 MVP игры Угадай число]]: одиночная консольная игра, всё на русском.
- Варианты диапазона для сравнения: 1–10 (слишком коротко?), 1–100 (классика, оптимум 7 попыток), 1–1000 (оптимум 10, партия затягивается). Критерий выбора — длина партии и ощущение, что подсказки ведут к цели.
- Оптимум при двоичном поиске: ⌈log₂(N + 1)⌉ попыток для N чисел — пригодится шкале оценки [[F04-01 Шкала оценки по попыткам]].
- ADR создаётся из шаблона плагина (`templates/adr.md`), в поле `task` — ссылка на эту задачу.
- Код в задаче не пишется.

## Проверка

1. ADR отвечает на все вопросы из критериев; зависимую impl-задачу можно делать, не возвращаясь к исследованию.
2. Каждое правило в ADR сформулировано так, что по нему можно написать тест («ввод `" 42 "` → 42», «`3.5` — ошибка, попытка не засчитана»).

# F02-02 Разбор догадки

> **Что:** функция в `src/input.js`, которая превращает введённую строку в число или в код ошибки по правилам ADR.
> **Зачем:** консоль получает либо корректную догадку, либо точную причину отказа.
> **Готово, когда:** `test/input.test.js` покрывает все допустимые и недопустимые виды ввода из ADR и зелёный.

## Критерии готовности

- [ ] Корректный ввод (в том числе с пробелами по краям и в формах, которые ADR разрешает) → целое число
- [ ] Пустая строка → `empty`; не число (`abc`, `12abc`, `1e2`, если ADR их не разрешает) → `notNumber`; дробное → `notInteger`; вне диапазона → `outOfRange`
- [ ] Обе границы диапазона принимаются, числа за границами на 1 — отклоняются
- [ ] Модуль не печатает и не читает ввод; строк интерфейса в нём нет
- [ ] `npm test` зелёный

## Детали

- Правила ввода — ADR из [[F01-01 Правила и диапазон]]; если ADR не отвечает на какой-то случай — спроси геймдизайнера, а не выбирай молча.
- Коды ошибок совпадают с ключами текстов из [[F02-01 Тексты ошибок ввода]] без префикса `error` (`empty` → `errorEmpty`). Если в ADR есть правило про повтор числа — это не забота разбора, его проверяет логика партии.
- Примерная форма: `parseGuess(line, { min, max })` → `{ ok: true, value }` или `{ ok: false, error }`.
- `Number('')` и `Number(' ')` дают `0`, а `parseInt('12abc')` — `12`: не опирайся на них без проверки.

## Проверка

1. `npm test` → все тесты `input.test.js` проходят.
2. В тестах есть хотя бы по одному случаю на каждый код ошибки и на обе границы диапазона.

# /task:replan — пересмотр плана

Скрипт плагина: `node "${CLAUDE_PLUGIN_ROOT}/scripts/tasks.mjs"` (дальше — «скрипт»). Аргументы: `$ARGUMENTS`.

Правила — в скиле `task:format` (разделы 8–9). Загрузи его, если ещё не загружен. Главное правило: **чужие задачи не меняются молча** — только после подтверждения человека и с записью в журнале каждой изменённой задачи.

## 1. Что выяснилось и где искать последствия

**Причина пересмотра** — из аргументов, из разговора, из журнала и ADR недавно закрытой задачи. Сформулируй её одной-двумя фразами и покажи пользователю.

**Область:**

| Аргумент | Что пересматриваем |
|----------|--------------------|
| `T-…` (обычно только что закрытая) | `скрипт affected <ID> --json` — незакрытые задачи, которые зависят от неё напрямую или по цепочке |
| `F-…` / `E-…` | `скрипт affected <ID> --json` — все незакрытые задачи фичи / эпика |
| `все` | все незакрытые задачи: `скрипт list --status draft,ready,in-progress,review --json` |
| ничего | последняя закрытая в этой сессии задача; непонятно — спроси |

Задачи `in-progress` у других исполнителей — только предлагай, отдельно отметив, что над ними уже работают.

## 2. Найти, что устарело

Прочитай каждую задачу из области и сравни с тем, что выяснилось:

- «Коротко», критерии или детали опираются на то, что оказалось не так (другое решение в ADR, другое имя, другой подход);
- задача стала не нужна (сделано в другой, решение её отменило) → `cancelled`;
- задача стала больше `L` или распалась на части → разбить;
- зависимость больше не нужна или появилась новая;
- не хватает задачи, без которой план не сходится → добавить.

Правь только то, что действительно следует из причины. Нечего менять — так и скажи.

## 3. Предложить — списком

```
Пересмотр после T-003 (ADR-002: HTML через markdown-it)

| Задача | Что меняем | Почему |
|--------|-----------|--------|
| T-005 Выгрузка в HTML | детали: markdown-it вместо своей генерации; критерий «без внешних пакетов» → «зависимость только markdown-it» | ADR-002 |
| T-007 Своя экранизация HTML | отменить | не нужна: экранирует markdown-it |
| + новая: Настройка markdown-it | добавить в F-02, зависит от T-003, size S | подсветка кода — отдельная работа |
```

Спроси: применить всё, частично или ничего? Без подтверждения ничего не меняй.

## 4. Применить

Для каждой подтверждённой правки:

- **Содержимое** (описание, критерии, детали) — правь файл. Затем запись в журнал без смены статуса: `скрипт set <ID> <текущий статус> --who "<роль> (Claude)" --log "план пересмотрен после [[<причина>]]: <что изменено>."`
- **Отменить** — `скрипт set <ID> cancelled --log "отменена при пересмотре после [[<причина>]]: <почему>."`
- **Зависимости** — поправь `depends_on` в файле + запись в журнал, как для содержимого.
- **Разбить** — новые задачи через `скрипт new …` (как в `/task:split`), исходную — сузить или отменить со ссылкой на новые.
- **Добавить** — `скрипт new …`, заполнить тело (как в `/task:create`), в журнале новой задачи — откуда она взялась.

Изменённые критерии — только с записью в журнале, почему (раздел 9 `task:format`).

Затем `скрипт check` (ошибок нет) и `скрипт board`.

## 5. Итог

Что изменено (по задаче одной строкой), что отменено и добавлено, что теперь готово к работе (`скрипт next`).

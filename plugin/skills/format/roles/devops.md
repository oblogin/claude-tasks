# Роль: devops

Отвечает за то, чтобы проект собирался, проверялся и доставлялся: окружение, сборка, CI, релизы, инфраструктура, хранение ассетов.

## Типы задач

- `task` — настройка сборки, пайплайна, окружения, скриптов.
- `research` — выбор инструментов и сервисов.
- `bug` — сломанная сборка, падающий пайплайн, проблемы окружения.

## Что писать в «Деталях»

- **Окружение** — где выполняется (локально, CI, сервер), версии инструментов.
- **Шаги** — что настроить и в каком порядке.
- **Секреты и доступы** — какие нужны и где хранятся. **Никогда не записывай сами значения** — только имя переменной или хранилища.
- **Откат** — как вернуть как было, если что-то пошло не так.
- **Влияние** — кого затронет изменение (другие роли, другие пайплайны).

## Критерии готовности

Проверяемый результат в окружении:

- ✓ «Пуш в `main` запускает сборку; сборка зелёная за < 15 минут»
- ✓ «Новый разработчик разворачивает проект по README за один проход»
- ✗ «Настроен CI» — что именно работает?

## Проверка

Команда или действие, которое доказывает работу (запуск пайплайна, чистая установка), и где смотреть результат (лог, артефакт).

## В журнал

Что изменено в инфраструктуре и где лежит конфигурация, ссылки на запуски пайплайна, известные ограничения, как откатить.

## Пример

```markdown
# T-031 Ночная сборка

> **Что:** собирать проект каждую ночь и сохранять артефакт сборки.
> **Зачем:** утром всегда есть свежая сборка для плейтеста.
> **Готово, когда:** три ночи подряд появляется артефакт, падение сборки приходит уведомлением.

## Критерии готовности

- [ ] Сборка запускается по расписанию в 03:00
- [ ] Артефакт хранится 7 дней, ссылка — в логе запуска
- [ ] При падении приходит уведомление в канал команды
```

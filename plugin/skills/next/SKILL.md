# /task:next — взять следующую задачу

Скрипт плагина: `node "${CLAUDE_PLUGIN_ROOT}/scripts/tasks.mjs"` (дальше — «скрипт»). Аргументы пользователя: `$ARGUMENTS`.

Правила работы с планом — в скиле `task:format` (раздел 9). Если он ещё не загружен в эту сессию — загрузи его.

## 1. Выбрать задачу

**Без ID** (можно с `--role <роль>`): `скрипт next --json [--role <роль>]`.
- Список пуст → скажи, что готовых задач нет, и покажи почему: `скрипт list --status in-progress,review` (что уже в работе) и строку «Заблокировано» из `Docs/Tasks/Board.md`. Предложи `/task:create`, `/task:replan` или взять задачу по ID. Дальше не иди.
- Иначе бери **первую** — это вершина очереди: задачи идут **по порядку плана** (сначала текущий спринт, внутри — по ID). Не переставляй очередь по своему усмотрению («эта меньше», «эта на критическом пути») — если считаешь, что порядок стоит поменять, скажи пользователю, а берёшь всё равно первую, пока он не решит иначе.

**С ID** (`T-042`): `скрипт show <ID> --json`.
- `done` или `cancelled` → скажи об этом и остановись.
- Есть незакрытые зависимости (`openDeps`) → перечисли их и спроси пользователя, брать ли всё равно. Нет → остановись.

## 2. Показать выбор

Коротко, в чат:

```
Беру T-042 Койот-тайм для прыжка  [must, S, gamedesigner]
Что: …  Зачем: …  Готово, когда: …
Другие готовые: T-045 …, T-047 … — если нужна другая, скажи или вызови /task:next <ID>.
```

Альтернативы — следующие 1–2 кандидата из очереди (для задачи по ID — не нужны).

## 3. Взять в работу

`скрипт set <ID> in-progress --log "взята в работу." --who "<роль задачи или твоя роль> (Claude)"` (добавь `--force`, только если пользователь согласился взять задачу с незакрытыми зависимостями).

Статус и журнал меняются этой командой сразу — до начала работы.

## 4. Работать

1. Прочитай файл задачи целиком: критерии, детали, проверку и **журнал** — там может быть контекст от предыдущих исполнителей.
2. Выполни задачу. Значимые решения, находки и отклонения от плана дописывай в журнал по ходу (раздел 9 `task:format`).
3. Выяснилось, что задача больше, чем казалось, или будущие задачи надо менять — не расширяй молча: скажи пользователю и предложи новую задачу, идею или `/task:replan`.

## 5. Закончить

Когда работа сделана — закрой задачу так же, как `/task:done`: отметь выполненные критерии, итоговая запись в журнал и статус через `скрипт set <ID> done|review --log "…"`. Если закрыть пока нельзя — оставь `in-progress` и запиши в журнал, на чём остановился.

# /task:next — взять следующую задачу

Скрипт плагина: `node "${CLAUDE_PLUGIN_ROOT}/scripts/tasks.mjs"` (дальше — «скрипт»). Аргументы пользователя: `$ARGUMENTS`.

Правила работы с планом — в скиле `task:format` (раздел 9). Если он ещё не загружен в эту сессию — загрузи его.

## 1. Выбрать задачу

**Без ID** (можно с `--role <роль>`): `скрипт next --json [--role <роль>]`.
- Список пуст → скажи, что готовых задач нет, и покажи почему: `скрипт list --status in-progress,review` (что уже в работе) и строку «Заблокировано» из `Docs/Tasks/Board.md`. Предложи `/task:create`, `/task:replan` или взять задачу по ID. Дальше не иди.
- Иначе бери **первую** — это вершина очереди: задачи идут **по порядку плана** (сначала текущий спринт, внутри — по ID). Не переставляй очередь по своему усмотрению («эта меньше», «эта на критическом пути») — если считаешь, что порядок стоит поменять, скажи пользователю, а берёшь всё равно первую, пока он не решит иначе.

**С ID** (`F03-02`): `скрипт show <ID> --json` — дальше по статусу задачи:
- `done` или `cancelled` → скажи об этом и остановись.
- `review` → задача ждёт проверки человеком. Предложи закрыть её после проверки (`/task:done <ID>`); в работу — только если пользователь просит доработку (тогда шаг 3 с `--log "возвращена на доработку: <что не так>."`).
- `in-progress` → над задачей уже работают. Покажи последнюю запись журнала и спроси: это твоя задача из прошлой сессии — продолжить, или её делает другой исполнитель — не трогать. Продолжаешь → шаг 3 с `--take` и `--log "продолжаю: <с чего начинаю>."`.
- `draft` → задача не готова: не хватает критериев или деталей. Предложи дописать её; в работу — только с согласия пользователя.
- Есть незакрытые зависимости (`openDeps`) или закрыт родитель (`parentClosed`) → перечисли и спроси, брать ли всё равно (тогда `--force`). Нет → остановись.

## 2. Показать выбор

Коротко, в чат:

```
Беру F03-02 Койот-тайм для прыжка  [must, S, gamedesigner]
Что: …  Зачем: …  Готово, когда: …
Другие готовые: F03-04 …, F04-01 … — если нужна другая, скажи или вызови /task:next <ID>.
```

Альтернативы — следующие 1–2 кандидата из очереди (для задачи по ID — не нужны).

## 3. Взять в работу

`скрипт set <ID> in-progress --log "взята в работу." --who "<роль задачи или твоя роль> (Claude)"` (добавь `--force`, только если пользователь согласился взять задачу с незакрытыми зависимостями; `--take` — если продолжаешь задачу, которая уже `in-progress`).

Статус и журнал меняются этой командой сразу — до начала работы. Скрипт запоминает, что задачу взяла эта сессия: если закончишь ответ, не записав итог или место остановки, хук напомнит.

## 4. Работать

1. Прочитай файл задачи целиком: критерии, детали, проверку и **журнал** — там может быть контекст от предыдущих исполнителей.
2. Выполни задачу. Значимые решения, находки и отклонения от плана дописывай в журнал по ходу (раздел 9 `task:format`).
3. Выяснилось, что задача больше, чем казалось, или будущие задачи надо менять — не расширяй молча: скажи пользователю и предложи новую задачу, идею или `/task:replan`.

## 5. Закончить

Когда работа сделана — закрой задачу так же, как `/task:done`: отметь выполненные критерии, итоговая запись в журнал и статус через `скрипт set <ID> done|review --log …`. Если закрыть пока нельзя — оставь `in-progress` и запиши в журнал, на чём остановился.

Итог с Markdown (`код`, `$`, кавычки) не передавай в `--log "…"` — оболочка его испортит. В bash — через stdin: `скрипт set <ID> done --log - <<'EOF'` … `EOF` (кавычки вокруг EOF обязательны); в PowerShell — допиши запись в «Журнал» правкой файла и вызови `set` без `--log` (раздел 9 `task:format`, «Запись журнала»).

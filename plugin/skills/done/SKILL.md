# /task:done — закрыть задачу

`/task:next` закрывает задачу сам, в той же сессии. Эта команда нужна, когда закрываем отдельно: работа шла без `/task:next`, растянулась на несколько сессий или задача ждала проверки человеком (`review`). Поэтому задача определяется по плану (статусу и журналу), а не по памяти разговора.

Скрипт плагина: `node "${CLAUDE_PLUGIN_ROOT}/scripts/tasks.mjs"` (дальше — «скрипт»). Аргументы пользователя: `$ARGUMENTS`.

Правила — в скиле `task:format` (разделы 8–9). Если он ещё не загружен — загрузи.

## 1. Какую задачу закрываем

- ID в аргументах → она.
- Нет ID → `скрипт list --status in-progress,review --type task,research,bug --json`. Одна задача, над которой работали в этой сессии, — она. Несколько или непонятно — спроси пользователя.

Прочитай файл задачи целиком.

## 2. Сверить критерии

Пройди по каждому критерию готовности и реши по фактам (что сделано в работе, результаты проверок, тесты):

- выполнен → отметь `- [x]` в файле;
- не выполнен → оставь `- [ ]` и запомни причину;
- сознательно снят или перенесён в другую задачу → зачеркни: `- [ ] ~~текст~~ → перенесено в [[F03-…]]` (с согласия пользователя);
- выполнен, но **подтвердить может только человек** (ощущение в игре, внешний вид, ручная проверка) → оставь `- [ ]` и отметь это.

Выполни шаги из раздела «Проверка» задачи, которые можешь выполнить сам. Не отмечай критерий, который не проверял.

## 3. Выбрать статус

| Ситуация | Статус |
|----------|--------|
| Все критерии выполнены и проверены | `done` |
| Остались пункты, которые проверяет человек | `review` |
| Не выполнено что-то существенное | спроси пользователя: закрыть с пояснением (`done`), оставить в работе (`in-progress`) или отменить (`cancelled`) |

## 4. Записать итог и закрыть

Одной командой — статус и итоговая запись журнала. Текст — через stdin (`--log -`): в итоге почти всегда есть `код`, пути и кавычки, а в `--log "…"` оболочка их портит (bash выполняет обратные кавычки, PowerShell превращает их в спецсимволы):

```
скрипт set <ID> <статус> --who "<роль> (Claude)" --log - <<'EOF'
готово: <что сделано одной фразой>.
- результат: <файлы, коммиты, где смотреть>;
- не выполнено: <пункт> — <причина> (если есть);
- что проверить человеку: <…> (для review);
- влияние на план: <что выяснилось для следующих задач> (если есть).
EOF
```

Кавычки вокруг `EOF` обязательны — тогда оболочка не трогает текст. Строки после первой скрипт сам оформит вложенным списком. Пустые пункты не пиши. В PowerShell here-doc нет: допиши запись в «Журнал» правкой файла (формат — раздел 9 `task:format`) и вызови `скрипт set <ID> <статус>` без `--log`.

## 5. Что дальше

Покажи пользователю коротко:

1. Статус и одна строка итога.
2. **Разблокированные задачи** (`unblocked` в выводе `set`) — теперь их можно брать: `/task:next`.
3. Если все задачи фичи закрыты (`parentComplete`) — предложи закрыть и фичу: `скрипт set <F-ID> done --log "все задачи закрыты."`.
   Задачу отменили (`cancelled`), а от неё зависят другие (`waiting`) — скажи об этом: им нужно поправить `depends_on` (`/task:replan`).
4. Спроси: выяснилось ли в работе что-то, что меняет будущие задачи? Если да — `/task:replan`.

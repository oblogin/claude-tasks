# /task:split — декомпозиция

Скрипт плагина: `node "${CLAUDE_PLUGIN_ROOT}/scripts/tasks.mjs"` (дальше — «скрипт»). Аргументы: `$ARGUMENTS`.

Правила — в скиле `task:format`: типы (раздел 3), **как написать хорошую задачу (8)**. Загрузи его, если ещё не загружен.

## 1. Что разбиваем

- `E-…` (эпик) → фичи. `F-…` (фича) → задачи (`task`, `research`, `bug`).
- Нет ID → спроси, что разбить (покажи эпики и фичи: `скрипт list --type epic`, `--type feature`).
- Прочитай файл целиком: «Коротко», «Цель/Входит/Не входит», решения, журнал.
- **Что уже есть**: `скрипт list --json` — дети этого элемента (`parent`) и похожие задачи в других местах. Их не дублируй: включи в предложение как «уже есть» или предложи дополнить.
- Непонятно главное (что входит, какой результат) — задай 1–3 вопроса, по одному, прежде чем предлагать.

## 2. Предложить разбиение — списком, без файлов

```
Разбиение F-03 Прыжок → 5 задач

| #  | Название                 | Тип      | Роль         | Размер | Зависит от | Что / Готово, когда                         |
|----|--------------------------|----------|--------------|--------|------------|---------------------------------------------|
| 1  | Модель гравитации        | research | architect    | S      | —          | выбрать модель / ADR с выбором               |
| 2  | Гравитация и падение     | task     | programmer   | M      | 1          | падение по модели из ADR / тест падения зелёный |
| …  |                          |          |              |        |            |                                             |
Уже есть: T-040 Ввод прыжка — остаётся как есть, №3 будет от неё зависеть.
Критический путь: 1 → 2 → 4.
```

Правила разбиения:

- Каждая задача — **один проверяемый результат**, размер не больше `L` (лучше `S`–`M`). Больше — разбей дальше.
- **Рискованное или спорное решение** (архитектура, выбор подхода, неизвестная технология) — отдельная `research`-задача с ADR, а реализация зависит от неё.
- Зависимости — только настоящие: «без результата A нельзя начать B». Задачи, которые можно делать параллельно, не связывай.
- `role` — свободная метка «кто делает»; если исполнитель не важен — не указывай.
- Для эпика: фичи — законченные возможности, которые можно показать; задачи внутри фич — по желанию пользователя (можно потом разбить каждую фичу отдельно).

Спроси: так? Правки — и снова список. **Без подтверждения файлы не создавай.**

## 3. Создать

1. Создавай **в порядке зависимостей** (сначала те, от кого зависят), чтобы ссылаться на уже выданные ID:
   `скрипт new <тип> --title "<название>" --parent <ID разбиваемого> [--depends <ID>,<ID>] [--role <роль>] --priority <p> [--size <s>] --status <draft|ready> --json`
   Запоминай соответствие «№ в списке → выданный ID».
2. В каждый созданный файл впиши тело: «Коротко» (Что / Зачем / Готово, когда), проверяемые критерии, «Детали» (что нужно исполнителю: на что опираться, ограничения), «Проверку». Удали все подсказки `<!-- … -->`. `ready` — если критерии и проверка готовы, иначе `draft`.
3. `скрипт check` — ошибок нет, предупреждения о новых файлах исправлены. `скрипт board`.

## 4. Итог

Список созданного (ID, название, статус), что готово к работе первым (`скрипт next`), и критический путь. Разбивали эпик — предложи следующим шагом `/task:split` для первой фичи.

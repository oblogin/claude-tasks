# /task:create — новая задача через обсуждение

Скрипт плагина: `node "${CLAUDE_PLUGIN_ROOT}/scripts/tasks.mjs"` (дальше — «скрипт»). Что сказал пользователь: `$ARGUMENTS`.

Правила — в скиле `task:format`: типы (раздел 3), поля (5), «Коротко» (7), **как написать хорошую задачу (8)**. Загрузи его, если ещё не загружен.

## 1. Понять контекст

- Посмотри план: `Docs/Tasks/Board.md` и `скрипт list --type epic`, `--type feature` — чтобы знать, куда задача может встать.
- Проверь, нет ли уже похожей задачи или идеи (`скрипт list --json`, поиск по названиям). Есть задача — скажи и предложи дополнить её вместо новой.
- **Задача из идеи** (пользователь назвал `I-…` или нашлась похожая идея) — идея становится отправной точкой: её «Что / Зачем» — начало разговора. После записи новой задачи закрой идею со ссылкой на результат: `скрипт set <I-ID> done --promoted-to <новый ID> --log "взята в план → <новый ID>."`

## 2. Обсудить — по одному вопросу

Задавай вопросы **по одному** (варианты — через AskUserQuestion, открытые — текстом), пока не станет ясно:

1. **Что** делаем — одним предложением.
2. **Зачем** — что это даёт.
3. **Готово, когда** — проверяемое условие; из него вырастут критерии.
4. **Тип**: `task` (работа), `research` (сначала выбрать решение → ADR), `bug` (что-то сломано), `feature` (законченная возможность из нескольких задач), `epic` (крупная цель).
5. **Место в графе**: родитель (фича для задачи, эпик для фичи) и от каких задач зависит. Предложи сам по плану — пользователь подтвердит или поправит.
6. **Кто делает** (`role`) — необязательно; свободная метка, любое слово (`programmer`, `artist`, имя агента…). Готового списка ролей нет — не предлагай его.
7. **Приоритет** (`must` / `should` / `could`) и **размер** (`XS`–`L`).

Не спрашивай то, что уже понятно из слов пользователя или из плана. Часть ответов можно предложить самому одним вопросом: «Предлагаю так: … — верно?»

**Слишком большая задача** (больше `L`, несколько независимых результатов, «сделать всю систему X») — предложи оформить её фичей и сразу разбить: после создания — `/task:split <F-ID>`.

## 3. Показать черновик

Покажи файл **целиком** — frontmatter и тело: «Коротко», критерии (проверяемые, по разделу 8 `task:format`), «Детали» (всё, что нужно исполнителю, чтобы не переспрашивать), «Проверка». Спроси: записывать? Правки — и снова черновик. Без подтверждения файл не пиши.

## 4. Записать

1. `скрипт new <тип> --title "<название 2–6 слов>" --parent <ID> [--depends <ID>,<ID>] [--role <роль>] --priority <p> [--size <s>] --status <draft|ready> --json`
   - `ready` — если есть критерии и понятно, как проверить; иначе `draft`.
   - Скрипт сам выдаст ID, папку, имя файла и frontmatter. Ошибка — поправь аргументы.
2. Открой созданный файл (`file` в ответе) и впиши согласованное тело вместо подсказок. **Удали все подсказки `<!-- … -->`**; необязательный раздел, в который нечего писать, убери («Коротко» и «Журнал» — не убирать).
3. `скрипт check` — ошибок быть не должно; предупреждения о новом файле — исправь.
4. `скрипт board` — доска обновлена.

## 5. Итог

Коротко: ID и название, статус, где в графе (родитель, от чего зависит, что будет ждать её), путь к файлу. Если задача большая — напомни про `/task:split`.

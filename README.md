# claude-tasks

Плагин **task** для [Claude Code](https://code.claude.com): план задач проекта в обычных Markdown-файлах, который одинаково удобно вести человеку и агентам.

- **Один раз разложить проект на задачи.** MVP → крупные фичи → задачи, с зависимостями между ними.
- **Давать задачи агентам командами.** «Возьми следующую» — агент сам находит задачу, у которой закрыты все зависимости, и берёт её в работу.
- **Корректировать план по ходу.** Закрыл задачу — агент предлагает поправить будущие, если что-то выяснилось.
- **Смотреть план в Obsidian.** Задачи — обычные заметки, связи — ссылки `[[…]]`, граф зависимостей строится сам. Плагины Obsidian не нужны.

> **Статус:** в разработке. Работают `/task:init`, `/task:create`, `/task:split`, `/task:next`, `/task:done`, скрипт проверки плана и доски; остальные команды — в работе (см. таблицу ниже). План разработки самого плагина ведётся в этом же формате — [Docs/Tasks/Board.md](Docs/Tasks/Board.md).

---

## Как это выглядит

План лежит в папке `Docs/Tasks/` вашего проекта:

```
Docs/Tasks/
├── Readme.md      ← что это за папка
├── Board.md       ← доска: готово к работе / в работе / заблокировано (генерируется)
├── Epics/         ← E-01 Прототип игры.md
├── Features/      ← F-03 Прыжок.md
├── Tasks/         ← T-042 Койот-тайм для прыжка.md
├── Backlog/       ← I-007 Кооператив.md   (идеи на потом)
└── Adr/           ← ADR-002 Модель гравитации.md   (принятые решения)
```

Любая задача начинается с блока **«Коротко»** — чтобы за несколько секунд понять, о чём она. Подробности любого объёма — ниже:

```markdown
---
id: T-042
type: task
role: gamedesigner
status: ready
priority: must
size: S
parent: "[[F-03 Прыжок]]"
depends_on:
  - "[[T-040 Гравитация и падение]]"
created: 2026-10-01
---
# T-042 Койот-тайм для прыжка

> **Что:** прыжок разрешён ещё 0.1 с после схода с края.
> **Зачем:** прыжки с платформ ощущаются честными.
> **Готово, когда:** прыжок срабатывает в окне, тест окна зелёный.

## Критерии готовности
- [ ] Прыжок проходит в течение `CoyoteTime` после потери опоры, после — нет
- [ ] Ощущение проверено руками в тестовой карте

## Детали
…любой объём: как делать, архитектура, ссылки…

## Проверка
1. …

## Журнал
- **2026-10-02 · gamedesigner (Claude):** взята в работу.
```

### Главное в формате

| | |
|---|---|
| **Уровни** | эпик (`E-01`) → фича (`F-01`) → задача (`T-001`); плюс идеи (`I-001`) и решения (`ADR-001`) |
| **Типы задач** | `task` — работа, `research` — сначала выбрать решение (результат — ADR), `bug` — исправление |
| **Статусы** | `draft` → `ready` → `in-progress` → `review` → `done`, плюс `cancelled`. «Заблокирована» не хранится — вычисляется по зависимостям |
| **Зависимости** | только в `depends_on` той задачи, которая ждёт. Кого задача блокирует — считает скрипт |
| **Роль** | `role` — свободная метка «кто делает» (`programmer`, `artist`, имя агента…). Готовых ролей нет |
| **Язык** | имена полей — английские, всё остальное — по-русски |

Полная спецификация — [plugin/skills/format/SKILL.md](plugin/skills/format/SKILL.md).

### Главное правило для агентов

Взял задачу — сразу `status: in-progress` и запись в «Журнал». Закончил — отметь критерии, поставь `done` (или `review`, если результат проверяет человек) и запиши итог. **Статус и журнал обновляются сразу, а не потом** — иначе доска начинает врать.

Это правило плагин доносит до агентов тремя путями: скил `task:format` с полной спецификацией, блок «Работа с задачами» в `CLAUDE.md` проекта (его добавляет `/task:init`) и хуки-напоминания (в разработке).

## Установка

Нужны Claude Code и Node.js (для скрипта плагина; Python не нужен).

```bash
claude plugin marketplace add C:\AI\claude-tasks
claude plugin install task@claude-tasks --scope user
```

- `--scope user` — плагин во всех проектах; `--scope local` — только в текущем репозитории.
- Терминал, десктоп-приложение и VS Code используют одни настройки — установленный плагин виден везде.
- Если сессия уже открыта — выполните `/reload-plugins`.

Попробовать без установки (только в терминале, на одну сессию):

```bash
claude --plugin-dir C:\AI\claude-tasks\plugin
```

## Команды

| Команда | Что делает | Статус |
|---------|-----------|:------:|
| `/task:init` | Создать `Docs/Tasks/` в проекте: папки, Readme, доска, правила для агентов в `CLAUDE.md`; по желанию — настройки Obsidian и `.gitignore`. Повторный запуск безопасен | ✅ |
| `/task:help` | Справка по командам | заглушка |
| `/task:create` | Обсудить с агентом, что нужно, и оформить задачу (эпик, фичу, research, баг) со связями в графе. Файл пишется после вашего подтверждения черновика | ✅ |
| `/task:split` | Разбить эпик на фичи или фичу на задачи с зависимостями; рискованные решения — отдельным research. Сначала список, файлы — после подтверждения | ✅ |
| `/task:next` | Взять следующую готовую задачу (или конкретную `T-042`, или `--role gamedesigner`), выполнить её и закрыть — весь цикл в одной сессии | ✅ |
| `/task:done` | Закрыть задачу отдельно: сверить критерии, записать итог, показать, что разблокировалось. Нужна, если работа шла без `/task:next`, растянулась на несколько сессий или задача ждала вашей проверки (`review`) | ✅ |
| `/task:replan` | Пересмотреть будущие задачи — правки только после вашего подтверждения | 🔧 |
| `/task:idea` | Записать идею в бэклог одной фразой | 🔧 |
| `/task:board` | Проверить план и пересобрать доску | 🔧 |

✅ — работает, 🔧 — в разработке. Команды вызываются с префиксом `task:`; без префикса тоже работают, если имя не занято встроенной командой (`/help` и `/init` — заняты).

### Типичный сценарий

1. `/task:init` — создать план в проекте.
2. `/task:create` — описать цель (эпик MVP), затем `/task:split` — разбить на фичи и задачи.
3. Открыть `Docs/Tasks` в Obsidian: «Открыть папку как хранилище».
4. `/task:next` — агент берёт задачу, выполняет и сам закрывает её. Повторять. `/task:done` — только когда закрываете отдельно (например, после своей проверки задачи в `review`).
5. Выяснилось что-то важное — `/task:replan`. Пришла мысль на потом — `/task:idea`.

## Obsidian

`Docs/Tasks` открывается как отдельное хранилище. `/task:init` может записать рекомендуемые настройки (по вашему согласию, при закрытом Obsidian):

- задача открывается сразу с блока «Коротко» — свойства скрыты в боковую панель, нет второго заголовка;
- граф без доски, узлы раскрашены по типам (эпики — красные, фичи — оранжевые, задачи — синие, ADR — зелёные, идеи — серые), у зависимостей есть стрелки.

Личные настройки Obsidian (`Docs/Tasks/.obsidian/`) лучше не хранить в git — `/task:init` предложит добавить их в `.gitignore`.

## Скрипт плана

Команды плагина опираются на скрипт `plugin/scripts/tasks.mjs` (Node.js, без зависимостей). Его можно запускать и напрямую — из корня проекта:

```bash
node plugin/scripts/tasks.mjs check            # проверить план: формат, ссылки, циклы, статусы
node plugin/scripts/tasks.mjs board            # пересобрать Docs/Tasks/Board.md
node plugin/scripts/tasks.mjs next --role qa   # задачи, готовые к работе, в порядке очереди
node plugin/scripts/tasks.mjs new task --title "Название" --parent F-01   # файл из шаблона
node plugin/scripts/tasks.mjs new-id task      # следующий свободный ID
node plugin/scripts/tasks.mjs show T-042       # карточка: «Коротко», критерии, зависимости, кого блокирует
node plugin/scripts/tasks.mjs set T-042 done --log "итог"   # статус + запись в журнал + доска
node plugin/scripts/tasks.mjs list --status in-progress
node plugin/scripts/tasks.mjs init --claude-md # создать план в проекте
```

`--json` — вывод для агентов и команд; `--root <папка>` — явный путь к плану.

**Что проверяет `check`:** циклы и битые ссылки, дубли и формат ID, имя файла и заголовок, папку по типу, обязательные поля и `parent`, допустимые статусы, приоритеты и размеры; предупреждает о пустом «Коротко», `ready` без критериев, `done` без записи в журнале или с неотмеченными критериями, `in-progress` при незакрытых зависимостях. Ссылки внутри `кода` не проверяются — это примеры.

**Очередь `next`:** задача `ready`, все зависимости `done` → сначала текущий спринт, затем приоритет, затем сколько задач она разблокирует, затем ID.

## Разработка

```
.claude-plugin/marketplace.json   ← репозиторий = локальный маркетплейс
plugin/                           ← сам плагин
├── .claude-plugin/plugin.json
├── skills/
│   ├── format/SKILL.md           ← спецификация формата (скил task:format)
│   ├── init/SKILL.md             ← /task:init
│   ├── create/SKILL.md           ← /task:create
│   ├── split/SKILL.md            ← /task:split
│   ├── next/SKILL.md             ← /task:next
│   ├── done/SKILL.md             ← /task:done
│   └── help/SKILL.md             ← /task:help
├── scripts/
│   ├── tasks.mjs                 ← check, board, next, list, show, set, new, new-id, init
│   └── test/                     ← тесты: node --test
└── templates/                    ← шаблоны задач и файлов проекта
Docs/Tasks/                       ← план разработки самого плагина (в плагин не входит)
```

- Плагин грузится прямо из папки репозитория: правки видны в новой сессии или после `/reload-plugins`, переустанавливать не нужно.
- Тесты: `node --test plugin/scripts/test/*.test.mjs`
- Проверка манифестов: `claude plugin validate ./plugin` и `claude plugin validate .`
- Проверить команду без установки: `claude -p "/task:init" --plugin-dir C:\AI\claude-tasks\plugin` в любой папке.
- Решения по устройству — [ADR-001](Docs/Tasks/Adr/ADR-001%20Устройство%20плагина.md).
